# Pallas Athena — core principles and specifications

Pallas Athena is the practice manager of one Québec civil-litigation lawyer. `athena/` holds its App Engine Standard services (no system libraries; memory local to each worker process): the default one (`main:app`: web app, DavX5 sync over CardDAV/CalDAV, MCP connector for Claude, cron and Cloud Tasks handlers) and the client « portail » (`client.wsgi:app`). Flask, Firestore, Firebase Storage, Jinja/HTMX/Alpine and precompiled Tailwind; no SPA, no deploy-time build. **A push to `main` runs the whole test suite, then deploys to production.**

Sources of truth: `models/*` and `services/*`, `mcp/disclosure.py`, `mcp/output_schemas.py`, `utils/deadlines.py`, `DEPLOYMENT.md` (operations), `SECURITY.md`, `athena/OBSERVABILITY.md`, `GABARITS_PLACEHOLDERS.md`. The previous long-form reference (per-collection fields, history) is `git show abc63b4:CLAUDE.md`; where it disagrees with the code or this file, it is stale.

**The claude.ai « Athena » connector tools available in a session act on PRODUCTION: never use them to test a change** (invoice numbers and register entries are permanent).

## Change Impact Assessment

These subsystems fail SILENTLY: tests pass and the breakage surfaces in production or on the phone. Before any change, say for each item whether it is touched and what you verified; the French commit message records it in an « Impact » paragraph, by item number. Code, tests and `DEPLOYMENT.md` cite these numbers.

1. **MCP connector** (`mcp/`, `templates/mcp/`). *Touches it:* `auth.py`, `security.py`, `config.py`, the OAuth collections, any model or service a tool reaches, a handler payload's shape. *Verify:*
   - What the connector can and can never do lives only in `mcp/disclosure.py`, from which `INSTRUCTIONS`, `mcp.tools.WRITE_TOOLS` and the consent screen's write block derive; the screen's read paragraph is hand-written (`templates/mcp/consent.html`): a new kind of data read updates it.
   - Every write runs through `mcp/write_support.run_write` with its declared `idempotency` policy (an edit also declares `concurrency`); an edit returns the entity built from the WRITTEN row. The scope gate stays in `endpoint._tools_call`; DAV-exposed writes follow item 2.
   - `mcp/output_schemas.py` is a MUST-conform contract: payload, schema and fixture move together; `required` gains only always-present keys, never one added to a shipped write output (same-key retries replay pre-deploy payloads).
   - Never widen a shipped tool's matches or defaults in place (unattended claude.ai tasks chain its reads into writes): add an opt-in argument.
   - A registry change can stale the claude.ai plugin (`exporter_plugin_athena --check` tells): fix `plugin/athena/`, rebuild and deliver it through the `athena-plugin` mirror (`plugin/athena/README.md`).
   - Nothing gates a token granted before a release: a new read or a widened write reaches it at deploy. When its consent text must be read first, ship revoke → deploy → re-consent (`DEPLOYMENT.md` §11).
2. **DavX5 sync** (`dav/`, model serializers and parsers, `services/dossier_dav.py`). *Touches it:* a serializer, parser or field they read, a CTag call site, the collection layout, any new write path to a DAV-exposed record (tool, script, cron, import). *Verify:* iCalendar output stays RFC 5545-valid with `UID`, `DTSTAMP` and `CREATED` (jtx Board needs `CREATED`), vCards (RFC 6350) carry `UID` and `REV`; serializers round-trip (served metadata is stripped on PUT); every write bumps `bump_ctag(dav.sync.collection_for(dossier_id))` (`"parties"` for a contact) at its call site — route, handler, service, script, or a model-level batch or cascade writer — inside the batch when batched; removals tombstone; moves go through `dav.sync.relocate_resource`. **DavX5 fails silently: verify with `curl` (recipes in `DEPLOYMENT.md` §15-16), then on the device.**
3. **Template generation / docx fill** (`utils/*docx*`, `utils/template_fields.py`, `services/gabarit*.py`). *Verify:* the engines substitute strings in the document, header and footer XML and copy every other zip entry byte-identical — never a `docxtpl`/`python-docx` round-trip, never a new part; every occurrence fills, split runs included; `resolve_values` maps every catalogue field and `GABARITS_PLACEHOLDERS.md` matches. **The generated .docx must open in Word without repair: check by hand, CI cannot see the repair prompt.**
4. **Observability & logging** (`utils/logging_setup.py`, `utils/tracing_setup.py`). *Touches it:* a new log line, span or user-facing data path. *Verify:* an event a metric or alert keys on goes through a typed `log_*` helper, and every event and span is registered in `athena/OBSERVABILITY.md`; structured fields land in `jsonPayload`; no second log handler appears (redaction sits on the one `init_app` builds); « Do not log PII » holds.
5. **Security & edge defense** (`security.py`, the `before_request` chain of `main.py`, `client/security.py`, the yaml files, Cloudflare and GCP). *Touches it:* headers or CSP, CSRF exemptions, rate-limit keys, request-size caps, path-prefix allowlists, a secret or setting name, a route under a special-cased prefix. *Verify* Security Rules. App Check (on htmx requests) and the origin check fail OPEN when unconfigured (logged once per process in production), so a dropped or renamed setting silently disables a layer; `python -m scripts.check_config` and Paramètres → Configuration report it.
6. **Frontend asset pipeline** (`static/vendor/`, `static/src/app.input.css`, `static/sw.js`, the base templates, the Early Hints lists in `security.py`). *Touches it:* a Tailwind class in a template, route or model, a vendored asset, a base template's scripts. *Verify:* **a class missing from the compiled CSS silently does not apply** — reuse a compiled class, or recompile and run the rehash fan-out (« Regenerating the stylesheet »); never edit a vendored file in place (cached immutable for a year); keep the footer order App Check boot → page scripts → htmx → Alpine, as execution follows document order.
7. **Firestore indexes & query invariants** (`firestore.indexes.json`, model queries). *Touches it:* a `where` + `order_by`, a new filter or sort field, a cursor-paginated list, a COUNT/SUM/AVG. *Verify:* the composite index **deploys before or with the code** — while it is missing or building the query fails and the view silently empties, and the test fake ignores indexes. Indexes are direction-exact: an ascending equality with a descending sort needs its own. A SUM/AVG needs its own index, trailing fields the aggregated ones in alphabetical order, directions matching the last sort, or the total silently reads zero. List views read bounded pages (`pagination.py`) or capped groups.

**Dependency bumps are a silent trigger.** A version-only diff can break these items: `icalendar`/`vobject` (DAV output), `google-auth`/`google-cloud-storage` (signing, uploads, object names in logs), `google-cloud-logging` (`jsonPayload`), `firebase-admin`/`pyjwt` (App Check), `pypdf` (document text), OpenTelemetry (trace-log correlation). Re-run the matching check before landing one.

## Architecture Rules

Code comments cite these numbers: keep them.

1. **Single user.** One authorized email (`AUTHORIZED_USER_EMAIL`): no tenancy, registration or roles. Every non-public main-service route declares its guard: `@login_required` (Firebase Auth with phone MFA, then the session), DAV Basic auth against a bcrypt hash, an MCP bearer token, or a machine route's App Engine cron or queue header. Only a fresh, unrevoked ID token opens a session, never for a portal account (claim `portail`): a signed cookie with no server-side store, expiring after `SESSION_LIFETIME_HOURS`, so rotating `flask-secret-key` ends them all.
2. **Firestore is flat.** Collections are top-level, linked by id fields (`dossier_id`), never nested under `users/{uid}`; a subcollection holds only records its parent owns (line items, steps, revisions, tombstones). In the main bucket, Storage paths live under `users/{uid}/` or `staging/{uid}/` (the portal's quarantine bucket keys by invitation).
3. **French for the user.** Every user-facing string is French. Write new code, comments and docstrings in English; modules already written in French (client/, Réception, French-named services, scripts and tests) keep their language. Québec legal terms stay French.
4. **Money in integer cents.** `15000` is 150,00 $, never a float; `Decimal` serves only intermediates (tax computations, parsing a typed amount), rounded `ROUND_HALF_UP` to the cent before storage. Parse and display money through `utils/format_fr`.
5. **UTC instants, Montréal days.** Store instants tz-aware in UTC and display them through `to_mtl`; store a date-only value at UTC midnight and never pass it through `to_mtl` (it would show the previous day). Take « today » and lateness only from `utils/deadlines` (`today_mtl`, `is_past_due`, `days_until`): templates read flags the route computed, never compare dates, and tests freeze `today_mtl` with a fixed deadline, never a widened offset.
6. **UUIDv4 ids.** The server mints them, never reuses one and discards ids a caller sends. Keyed ids are exceptions declared in their module's docstring; one that two writers could create at once is written with `create()`, never `set()`.
7. **`created_at`, `updated_at`, `etag` (+ provenance).** Every record a user or the connector edits carries them; each write regenerates the etag with the `*_via` stamps (`models/provenance.py`): `updated_via` comes from the writer's context, never from an argument (a creator may name a valid `created_via`). A write given `expected_etag` commits only against that version, checked inside a transaction (`models/concurrency.py`); send the target state, never a toggle. Bookkeeping (`counters`, `dav_sync`) and records never edited under compare-and-set (journals, versions, revisions, credentials) carry no etag.
8. **HTMX first.** Return a fragment when `routes/_helpers.is_htmx()` is true, the full page otherwise. htmx swaps only 2xx: a refusal re-renders at 200 or redirects with `?erreur=`; a filter-dependent element outside the `hx-target` is re-emitted with `hx-swap-oob`.
9. **Mobile-first.** Design at 375 px, then widen at the `md` and `lg` breakpoints; touch targets measure at least 44 px.
10. **Minimalist visual language.** `#FAFAFA` background, `gray-900` text, `indigo-600` accent; Noto Sans for the UI, Noto Serif only for reading surfaces (`.note-content`, PDF exports). Icons render only through `ms()` (`utils/icons.MATERIAL_ICONS`), which is `aria-hidden`, so an icon-only control carries `aria-label` and `title`; a new icon needs the vendored subset regenerated (`utils/fonts/README.md`) and a browser check.
11. **DAV-ready records.** Parties, hearings, tasks and notes carry a vCard/iCal UID (`vcard_uid`, `vevent_uid`, `vtodo_uid`, `vjournal_uid`) minted at creation, or taken from the DAV client's create, and never changed.

## Design principles

- **One door per rule.** Rules and writes live in `models/`: normalize, sanitize, then validate a whitelist of keys. Identity, stamps, provenance and payment state never come from the caller; `_sanitize_data` covers only top-level strings, so `_normalize` sanitizes nested free text. `services/` orchestrate without owning rules; `utils/` domain computations import neither Flask nor `models/`. Web, DAV, connector and cron use that door; each derived value has one authority (`invoice.balance_of`, `dossier.derive_prescription`, `template_fields.selected_address`). A one-shot migration or repair script writing around it says so in its docstring, regenerates etags with the stamps and bumps the CTags it affects.
- **A failed read never passes for absence.** A read that decides a write, a refusal or « none found » uses a `*_strict` reader that raises; fail-open readers serve display only. Refuse a blank id before querying (`''` matches every record without a parent); a caller's id holding « / » or refused by Firestore is absent (`document.is_addressable_id`). Nor does a capped read pass for complete: a list says it is truncated, and a total or decision built on a truncated one raises. A sweep that deletes because something is absent first proves its read complete. DAV answers a failed read with an error DavX5 retries (503 + `Retry-After`, or 500 for a failed CTag read), never a 404 or a short listing (DavX5 deletes local data on those) nor a 412 (a false edit conflict).
- **Merge by presence; grow the schema additively.** An absent key keeps the stored value; a present empty key erases it. Parsers omit what they did not receive; a normalizer adds no key the caller did not send (defaults apply on creation or to the merged record). Legacy documents lack new keys (a Firestore equality on `None` never matches an absent one): migrate on read (`_migrate_*`), purge on save. A new rule judges only the fields a write carries and refuses only what the change makes worse, so legacy data never locks a record.
- **Honest outcomes.** Refuse rather than degrade: never round input, default an unresolvable reference (« Général », the root folder) or settle contradictory arguments by precedence; batches are all-or-nothing. A new write path refuses what `security.sanitize` would alter, never truncates or strips it. Validate the exact string to be stored (textareas send CRLF) and explain refusals in French; a disabled button is no guard. After the main commit, follow-on effects never raise: log ids, report the operation incomplete. A lost commit answer is « uncertain »: re-read to settle it, never report « nothing written ».
- **The lawyer decides.** Machine judgments — a compliance check Claude inscribes, a document's category or analysis — are stored « présumé »; name matches and suggested délais are only proposed. Only the lawyer confirms, in the web UI; no automatic path confirms, overwrites or lowers what he chose or confirmed (a category, a KYC or conflict status, a protection level).
- **Records are permanent.** Replaced note text goes to `revisions` in the same transaction; budget versions, analyses, template versions and `audit_events` are write-once. A still-referenced contact or dossier refuses deletion; each hard delete appends one `audit_events` row after its commit. Sequence numbers come from `counters/{scope}` inside the writing transaction, never reused.
- **One source per list.** Derive every list, enum, count and fan-out from its single source and pin it with a test; never restate a count or inventory in prose — this file's data model map is the one deliberate exception. Compare vocabulary keys with `==` or a dict lookup, never `startswith`. Stored keys and slugs change only through a one-shot migration: a rename changes the label. Declare every exception to a house rule in its module's docstring.

## Security Rules

- **Edge.** All external traffic transits Cloudflare, enforced on both services by the App Engine firewall (Cloudflare's ranges plus the cron and Cloud Tasks address; `DEPLOYMENT.md` §7), the `X-Origin-Auth` origin secret and the refusal of `*.appspot.com` hosts; only that lets `CF-Connecting-IP` key rate limits. Only `/_ah/` paths and requests carrying `X-AppEngine-QueueName` or `X-Appengine-Cron`, which App Engine strips from external traffic, skip those checks (`security.is_appengine_internal_request`) — never the `X-AppEngine-` prefix, which its geo headers share; each machine handler re-checks its header.
- **CSRF.** Every browser write carries the token. Never put a browser route on a CSRF-exempt blueprint (DAV, MCP, the machine `taches_*`) or under a special-cased prefix; a machine endpoint gets its own blueprint.
- **CSP** is enforced with a per-request nonce: inline scripts only as `<script nonce="{{ csp_nonce }}">`, no inline `on*` handlers (`addEventListener` on `data-` attributes), server data in `<script type="application/json">`, Alpine `x-data` values through `|jsattr`; assets are vendored, never from a CDN (Google's script origins serve only App Check's reCAPTCHA). App responses are `no-store`; the service worker caches only `/static/vendor/`, `/static/icons/`, `owl.png` and the offline page, never HTML, fragments or signed URLs.
- **Secrets** come only from Secret Manager through `config.py` and `client/config.py` (env vars locally), never from yaml, code or logs (inventory: `DEPLOYMENT.md` §4). Compare them with `hmac.compare_digest` on bytes. Check every expiry in code on read: Firestore TTL only garbage-collects.
- **Inputs and errors.** Check query-string filters against their `VALID_*` vocabulary. Request-supplied redirect targets go through `security.safe_internal_redirect`; a stored URL rendered as a link passes its http(s) allowlist (`models/hearing.is_safe_conference_uri`). Users see a French sentence chosen by error type, never `str(exc)`. Regexes over untrusted text stay linear (CWE-1333).
- **Storage.** Paths take their uid only from `utils/storage_identity`, which fails closed (never `"unknown"`). Stored files never transit Flask (App Engine caps a request and a response at 32 MB): uploads go browser → GCS through resumable sessions, copies stay GCS-side, downloads use 15-minute signed URLs, never a raw bucket URL. Only a gabarit's small .docx is posted to the app, and only generated output (exports, fills, prints) streams from it. Write the object before its record. Firestore and Storage rules deny every client.
- **Tool outputs.** `begin_upload`'s write-only `upload_url` is the ONLY capability a tool output may carry: create-only, bound to one neutral staging object, filed by `finalize_upload` only if size and MD5 match, never persisted or logged.
- **Do not log PII.** Logs, span attributes and exception messages carry ids, codes, field names and counts — never names, titles, free text, tokens or secrets, and no amount but a reconciliation variance. Redaction scrubs emails, phone numbers and postal codes, not names or court-file numbers, and `span()` exports exception text unscrubbed. Wrap interpolated request values in `sanitize_log_value`.

## Core specifications

- **Data model** (orientation only; each model's docstring holds the shape). Cases: `parties`, `dossiers`, `folders`, `documents` (`/analyses`), `notes` (`/revisions`), `tasks`, `hearings`, `protocols` (`/steps`). Billing: `timeentries`, `expenses`, `invoices` (`/lineitems`), `budgets`. Accounting: `trust_accounts`, `trust_transactions`, `trust_reconciliations`, `admin_accounts`, `admin_transactions`, `admin_reconciliations`. Templates: `doc_templates` (`/versions`). System: `settings` (`cabinet`, `integrations`), `counters`, `audit_events`, `dav_sync` (`/tombstones`), `oauth_clients`, `oauth_codes`, `oauth_tokens`, `mcp_idempotency`, `mcp_upload_tickets`. The portal's named database « portail » holds `invitations`.
- **Contacts and dossiers.** Each contact is one `parties` document (a vCard) whose `contact_role` describes the contact itself. A dossier's clients, opposing parties, roles and per-party counsel live in its party arrays (names snapshotted); `client_ids`, `opposing_party_ids` and `avocat_ids` mirror them only for `array_contains` queries, and rules read the arrays. Addresses resolve through `utils/template_fields.selected_address` (not the invoice's billing snapshot, `invoice.billing_address_from`, by design), identity and conflict statuses through `utils/kyc.apply_status_transition`, a court file number's greffe and juridiction through `models/reference.py`, never the `ref_*` mirror.
- **Invoices and taxes.** TPS (5 %) and TVQ (9,975 %) apply to the same taxable base, never compounded; stored rates use different scales (`gst_rate` ×100, `qst_rate` ×1000). A time entry or expense sits on at most one live invoice and, once drawn in, is frozen except for its phase; only a void releases it. Generated numbers (`YYYY-F###`, per Montréal year) come from `counters/invoices-{year}`; an imported number keeps its form and never touches the counter. Only a `brouillon` is corrected, and `amount_due` is frozen at issuance. A payment exists only as a register entry (administration encaissement or trust fee payment): « payée » follows the registers, never a status change, and « envoyée » sends nothing.
- **Accounting registers.** Trust (client funds) and administration (the firm's funds) are parallel, never merged or totalled together. Trust is append-only and sequence-ordered: an entry changes only through its clearing lifecycle, is corrected by a reversal dated today, and overdraft is checked against the cleared balance inside the transaction. An administration entry stays editable while no completed reconciliation locks its period. A fee payment commits the trust withdrawal, the administration recette and the invoice payment in one transaction (`models/fee_payment.py`). The web and the connector create, pay, reverse, clear and edit entries through `services/comptabilite.py`.
- **Délais and prescription.** `utils/deadlines.py` counts court delays under art. 83 C.p.c. on the `PROCEDURAL` calendar (the default, with art. 82 holidays); prescription and other C.c.Q. delays pass `regime=CIVIL` (art. 2879). Lateness counts from the prorogued deadline. A recurring series (`utils/recurrence.py`) anchors every occurrence on the series' start, converts each through `tz.mtl_to_utc` and never moves one off a non-juridical day. `prescription_date` derives on save from `droit_action_date` and `prescription_type`, never from prescription events; every prescription status and alert reads `dossier.derive_prescription` (the Aperçu tab and `dossier.date_pour_agir` show the raw date). `utils/taxonomie.py` suggests each recourse's délai; every computed délai is indicative.
- **DAV.** Every collection is a direct child of `/dav/` (DavX5 discovers them by a Depth:1 PROPFIND of the root): `addressbook/` (parties), `general/` (hearings, tasks and notes without a dossier) and one `dossier-{id}/` (VEVENT, VTODO and VJOURNAL) per dossier whose status is in `dav.sync.ACTIVE_DOSSIER_STATUSES`. Each item lives in exactly one collection; `dav_sync/{name}` holds its CTag (also the sync token) and tombstones. A dossier's status changes only through `services/dossier_dav.run_status_transition`, which drains or restores its collection. Hrefs are permanent: a layout change means re-adding the DavX5 account.
- **MCP connector.** Stateless JSON-RPC over Streamable HTTP at `POST /mcp` (no SSE, no sessions; registry `mcp/tools.py`) behind an embedded OAuth server (PKCE, rotating refresh tokens, sha256-stored tokens, Claude's callbacks only, a French consent screen behind login and MFA). Scopes are `athena:read` and `athena:write`: every write tool, accounting included, needs `athena:write`, granted only by the consent screen's write box and frozen at issuance; every read, the administration ledger's included, needs `athena:read`. The connector is always on; to stop it, revoke every token (`python -m scripts.revoke_mcp_tokens`): writes re-validate the token and stop at once, reads when the bearer cache expires.
- **Client portal.** `athena/client/` never imports the main service's `models`, `security` or `config`; it reads only the « portail » database (the invitations), which only the main service writes, and signals that service through Cloud Tasks. Clients sign in by a Firebase email link bound to the invited address; every request re-reads the invitation, and the public portal can read every invitation field, so none carries a dossier title or a memo. Uploads land in a create-only quarantine bucket. Nothing is filed before the lawyer's « Verser » in Réception.
- **Bookings and Outlook.** A cron imports Bookings reservations as hearings whose `confirmation` (not `status`) is « à_confirmer »: DAV, the dashboard and the connector's default reads skip them pending the lawyer's decision, in Réception or through `decide_rendez_vous` (both via `services/rendez_vous.py`). A refusal cancels the client's Outlook meeting, the connector's only outbound effect (`mcp.tools.OUTBOUND_TOOLS`); the web app also emails clients through Graph (`utils/courriel.py`). Another cron mirrors confirmed, non-cancelled, non-Bookings hearings one way into the lawyer's Outlook calendar, writing nothing to Firestore and never adding attendees.
- **Documents and gabarits.** Folders form a Firestore-only tree per dossier (`models/folder.DEFAULT_TREE`); system folders carry a `system_role` and are found by it, never by name. A missing one is created at a deterministic id, unless an unstamped folder of its name sits under its parent: that folder is ADOPTED (stamped and locked, id kept), at tree creation as at use time. A gabarit is a .docx whose `{{placeholders}}` are auto, manual or passthrough (`GABARITS_PLACEHOLDERS.md`); template versions only grow, and a special-kind template (note d'honoraires, note print) applies only once the lawyer designates it « actif ». Notes are Markdown, rendered only through `utils/markdown_docx.markdown_to_safe_html`.
- **Protocols and the théorie de la cause.** A protocol is `cq_simplifié` (C.p.c. deadlines, locked), `cs_ordinaire` (suggested dates the lawyer confirms) or `conventionnel`; a dossier has at most one « actif » protocol, and only it is editable. A task linked to a step mirrors the step's completion and reopening both ways; a cancelled task is never rewritten. A dossier has at most one « Théorie de la cause » note (`is_analyse`), undated, which never leaves its dossier.

## Regenerating the stylesheet

The `@source` lines of `athena/static/src/app.input.css` are the complete scan set: a class outside them, or assembled at runtime, silently never compiles. From the repo root:

```bash
TW=$(sed -n 's/.*@tailwindcss\/cli@\([0-9.]*\).*/\1/p' athena/static/src/app.input.css)
npm install --no-save --no-package-lock "@tailwindcss/cli@${TW:?}" "tailwindcss@${TW:?}"
npx "@tailwindcss/cli@${TW:?}" -i athena/static/src/app.input.css -o athena/static/vendor/app.css --minify
H=$(sha256sum athena/static/vendor/app.css | cut -c1-8)
mv athena/static/vendor/app.css "athena/static/vendor/app.$H.css"
```

Delete the old `app.*.css` (exactly one may exist) and replace its name wherever it appears: `DEPLOYMENT.md` §15 « Frontend assets » is the authoritative, test-pinned list, and `git grep -l` confirms it (`tests/test_security_headers.py` included). Bump `STATIC_CACHE` in `athena/static/sw.js` and delete `node_modules`. Every other vendored asset takes a new name with new content — a content hash (`appcheck-boot.<hash>.js`, the icon subset: sha256 of the LF bytes git stores) or the upstream version — and every reference moves.

## Adding a feature

- Record a new collection's shape in its model's docstring, with its DAV UID field if DavX5 sees it, and add its name to the data model map.
- Extend existing models rather than add parallel ones: writers return `(doc, errors)` with French errors; a fail-open `get_X` sits beside `get_X_strict`.
- An edit form of a record the connector writes carries `{{ etag_field(record) }}` and `{{ conflict_banner(conflict) }}`; its route goes through `routes/edit_conflict.py` (`submitted_etag()`, `resolve_refusal`).
- Test through real routes, models and templates on `tests/_fake_firestore.py`; every guard proves it catches something, and every fix adds a test that fails on the old code.
- Edit this file only when a principle or a specification changes, never for history, counts or inventories.
