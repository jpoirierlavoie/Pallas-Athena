{# Reusable pagination controls. Two modes (pagination.mode): - "cursor" (preferred): expects next_cursor/next_trail/prev_cursor/prev_trail built by pagination.cursor_pagination(); hx-vals carries the opaque tokens. - "page" (legacy): expects page/has_prev/has_next; hx-vals carries the number. Both expect: url, target. Optional: extra_vals dict for extra hx-vals params. Both modes also carry pagination._nav()'s identical key set (has_total, last_page, prev/next/jump targets, show_* and *_possible flags), which is what lets ONE block of markup serve both with no arithmetic in the template. EVERY live control emits "page". Carrying it only on the leap cluster would let the label collapse to 3/4/5 while the data read 13/14/15, and would leave the freeze-at-22 bug in place. The leap controls are mode-agnostic: they emit an EMPTY cursor and trail, which is precisely what routes the request to the route's absolute-page branch. Clearing them is safe because cursors are not form fields, so hx-include cannot reintroduce one. ── ONE ROW, COUNTER BELOW (2026-09-11) ───────────────────────────────── Six glyphs, no label text: chevron (walk one page), double chevron (leap ±jump_size), bar-chevron (first / last page) — ordered by DESTINATION (1, p−10, p−1, p+1, p+10, L), a spatial number line that also keeps the two long-range controls at the outer edges, so a mis-tap on « Suivant » costs 10 pages instead of a jump to the end. * A glyph is the control's ONLY affordance, so every button needs BOTH `aria-label` (ms() renders aria-hidden, so the glyph contributes nothing to the accessible name) AND `title` — with no text, hover on a desktop and long-press on a phone are the only ways to learn what a button does. A DISABLED button keeps both: a screen reader still reads it in browse mode, and an unnamed grey square is unidentifiable. * Geometry: `.ms-20` is 21 px (app.input.css — the .ms-N names are deliberately offset from their pixel size), so `px-3 py-3` + a 1 px border is 47 × 47, clearing the Rule-9 minimum of 44. Six of them are 282 px against ~343 px of usable width at 375 px (max-w-4xl px-4). The counter moved to its own line to free the ~85 px it ate inline — which is what made one row impossible before, not the buttons. * `justify-between` with NO gap, not `justify-center gap-2`: padding is rem while the glyph is px, so at a root font-size of 18 px the gapped row needs 345 px against 339 px and CLIPS the last control — « Fin », whose title carries the destination number. So the button under the finger never moves during a walk, and no control is drawn that is dead on every page of the list. Slot counts, constant per list: 2 pages → 2 · 3-11 → 4 · ≥12 → 6 · no total → 3. « Début » survives the countless case because page 1 is offset 0, and it is the only escape from a deep countless walk (« Précédent » moves one page and the trail caps at MAX_TRAIL). Caveat worth knowing: has_total is recomputed per request, so an INTERMITTENTLY failing count still flips the bar 6 ↔ 3 mid-walk. A disabled control carries NO hx-* attribute at all — `:disabled` is not a guard (DevTools re-enables any button), and it also keeps a None jump target out of the emitted JSON. Its class string OMITS hover:bg-gray-50 and cursor-pointer: CSS :hover matches a disabled element and Tailwind adds no :not(:disabled), so an inert button would light up. That rule lives inside @media (hover:hover), which makes the defect invisible on the phone and visible on a desktop.
